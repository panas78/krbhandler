# krbctl — Kerberos Handler for the Linux desktop

A tray icon and a native GTK4 window for MIT Kerberos. It answers the two
questions you actually have — *is my ticket still good?* and *please renew it* —
without remembering that `kinit -k -t ~/.keytab user@REALM` is a thing.

Built to run anywhere: Noctalia, Waybar, KDE Plasma, GNOME with the AppIndicator
extension. It speaks `org.kde.StatusNotifierItem` + `com.canonical.dbusmenu`
directly, so there is no GTK3/X11 dependency and no libappindicator.

The icon is Cerberus — the three-headed dog who guards the gates, which is
exactly what "Kerberos" means.

It appears in the **launcher** icon, which is a static PNG set under
`data/icons/hicolor/` — nine sizes, committed, copied into place by `install.sh`.
No image tooling is needed to install or run this.

In the **tray**, you get the app's own icon, with the state as a small corner dot
that appears only when there is something to act on:

| (no dot) | amber | orange | red | grey |
|---|---|---|---|---|
| valid | expiring soon | cache unreadable | expired | no ticket |

A healthy ticket is the quiet case: just the icon, no annotation competing with
every other icon in the bar. The dot is ringed in near-black so the colour still
separates from the artwork behind it. It is drawn at runtime by
`krbctl/icons.py`, which loads the installed `krbctl.png` from the icon theme and
falls back to the older solid plate if the icon set is missing.

In the **window**, each account row keeps a solid plate instead, because a colour
chip beside a name reads faster than a picture would.

Clicking it gives two entries: **Open Kerberos Handler** and **Quit**. Everything
about a ticket — its state, renewing, destroying, removing — is in the window, so
mirroring it in the menu only produced a smaller copy that lagged behind.

## Why it exists

`kinit` + a systemd timer gets you a ticket. What you do not get is:

* a **countdown** you can glance at, instead of typing `klist`;
* a **renew** button for the 15 minutes before a ticket dies;
* a **sane failure** when the KDC is unreachable because the VPN is down —
  the timer just logs `Cannot contact any KDC` every hour, forever;
* somewhere to hold **more than one account**, with a password in the keyring
  for the ones that cannot use a keytab.

That is this app.

## Features

| | |
|---|---|
| **Live state** | valid / expiring / expired / no ticket / cache error, polled every 30 s |
| **Tray icon** | StatusNotifierItem showing the app icon with a state dot, a tooltip, and a two-entry menu: *Open Kerberos Handler* and *Quit* |
| **Native window** | GTK4 + libadwaita; accounts, ticket detail, renew, destroy |
| **Auto-renew** | renews from the keytab when the ticket is inside the warning window |
| **Backoff** | a failing renewal backs off 5 minutes instead of hammering a dead KDC |
| **Multiple accounts** | per-account cache (`KCM:`, `KEYRING:`, `FILE:`) or the session default |
| **Passwords** | stored in the Secret Service via libsecret, or asked each time |
| **Keytab creation** | builds one from a password with `ktutil` — no incantations |
| **Notifications** | expiring, expired, and renewal failure |
| **Scriptable** | `krbctl status --json` for bars, scripts and cron |
| **Zero config** | seeds the account on first run from `~/.keytab`, or from a ticket your login session already holds |
| **Domain join** | joins the machine to Active Directory, so a fresh install gets tickets without a shell script |

## Install

```bash
git clone https://github.com/panas78/krbhandler.git
cd krbctl
./install.sh
```

That single command creates:

| Put where | What |
|---|---|
| `~/.local/share/krbctl/` | the application |
| `~/.local/bin/krbctl` | launcher on `PATH` |
| `~/.local/share/applications/io.github.pan.Krbctl.desktop` | menu entry |
| `~/.local/share/icons/hicolor/*/apps/krbctl.png` | icon at 9 sizes |
| `~/.local/share/metainfo/` | AppStream metadata |
| `~/.config/autostart/krbctl-tray.desktop` | tray on login |

Both `.desktop` files are validated with `desktop-file-validate` during install,
because a malformed entry silently appears in no menu at all.

The autostart entry is generated by the app (`krbctl/autostart.py`), not written
by the installer, so the switch in the window, `krbctl autostart` and
`install.sh` cannot drift apart. Turning it off writes `Hidden=true` rather than
deleting the file — that is the XDG spec's masking mechanism, so disabling still
works if krbctl was also installed system-wide.

The GUI stack comes from the distro (`python3-gobject`, `gtk4`, `libadwaita`,
`python3-cairo`, `libsecret`, `krb5-workstation`), **not** from pip — those
packages ship typelibs that must match the system libraries, and a venv
PyGObject routinely cannot see them.

```bash
./install.sh --no-autostart   # install without starting the tray on login
./install.sh --uninstall      # remove everything it installed
```

## Use

The window has three tabs:

| Tab | What is on it |
|---|---|
| **Tickets** | one section per account: state badge, details, renew / sign in, destroy, remove |
| **Domain join** | `Not joined` with the missing package names, or the realm you are joined to with its login policy, plus the Join… / Leave button |
| **Options** | start at login, automatic renewal, and desktop notifications |

Options writes straight to `accounts.json`, so the poller and the tray pick a
change up immediately — no restart.

```bash
krbctl gui                   # open the window
krbctl tray                  # tray icon in the foreground
krbctl status                # one line per account
krbctl status --json         # machine readable
krbctl renew                 # renew now
krbctl destroy               # drop the ticket
krbctl doctor                # what is missing on this machine
krbctl autostart             # is the tray set to start on login?
krbctl autostart on|off      # change it
```

### Joining a domain

Tickets only exist once the machine is joined, so the join lives here too — in
the window, and on the command line for a machine you reach over SSH:

```bash
krbctl domain                  # readiness and membership
krbctl domain discover         # ask DNS about the realm
krbctl domain install          # install realmd / sssd / adcli / oddjob
krbctl domain join -U admin    # join; prompts for the password
krbctl domain check --user me  # verify a domain account resolves
krbctl domain leave            # leave
```

`krbctl domain status --json` prints the same readiness checks the window shows,
so a provisioning script can gate on `ready`.

The Domain row names the client software per realm — `Joined to example.com
(sssd)`.

`realm list` is not the whole truth, because it enumerates joined realms by
reading each client's config file. A leftover `/etc/samba/smb.conf` with
`security = ADS` therefore makes it report a winbind membership on a machine
with no winbind installed. krbctl checks whether each named client's systemd
unit actually exists, so:

* a **live** membership is shown in the row and is what `Leave` targets;
* an entry whose client is missing is called out as leftover config, not a
  second join — the repair is to deal with the stray config file, **not** to
  rejoin;
* if **two installed clients** really do hold one domain, that is the dangerous
  case and it says so: both rotate the machine account password independently,
  so a stale copy ends as "the trust relationship failed".

The joining password never reaches `realm`. It is used to obtain a Kerberos
ticket for the joining account, and realmd then runs with `--no-password
--unattended` using that ticket. The ticket lives in a throwaway `FILE:` cache
and is destroyed when the join finishes — so no password appears in a command
line, and no credential outlives the operation.

Root is requested through `pkexec`, which raises the desktop's own
authentication prompt instead of a terminal. Unattended `sudo` is used where it
is configured.

`status` exits `0` when everything is valid, `1` when a ticket is expiring,
expired or missing, and `2` on a cache error — so a bar module or a cron job can
branch on it.

## Status bars

**Noctalia / Waybar / KDE / GNOME AppIndicator** — nothing to configure. The app
registers an SNI item named `krbctl` with `org.kde.StatusNotifierWatcher`; the
host picks it up. Hosts that show only a few tray icons (Noctalia collapses the
rest behind an expander) may hide it, which is why `krbctl status --json` also
exists for a text badge.

**Waybar `custom` module:**

```json
"custom/krb": {
  "exec": "krbctl status --json --compact",
  "interval": 30,
  "return-type": "json",
  "format": "{}",
  "exec-if": "which krbctl"
}
```

**Anything with a script hook** — read `.accounts[0].badge` from the JSON.

## Layout

```
krbctl/
├── krbctl/
│   ├── kerberos.py   # klist/kinit/kdestroy/ktutil wrappers + state machine
│   ├── config.py     # accounts.json, first-run auto-detect
│   ├── secrets.py    # libsecret password storage
│   ├── autostart.py  # start-at-login entry (XDG autostart)
│   ├── domain.py     # Active Directory join / leave via realmd
│   ├── cli.py        # krbctl status/renew/destroy/doctor/...
│   ├── icons.py      # tray state plates, rendered at runtime
│   ├── tray.py       # StatusNotifierItem + DBusMenu over Gio
│   ├── window.py     # GTK4 / libadwaita window
│   └── app.py        # poller, auto-renew, notifications
├── data/
│   ├── icons/hicolor/     # launcher icon set, one dir per size
│   ├── krbctl.desktop.in  # launcher entry template
│   └── *.metainfo.xml     # AppStream metadata
├── tools/
│   └── tray-probe.py      # isolates tray/D-Bus problems
├── tests/                 # parsing + classification, no KDC needed
└── install.sh
```

Design rule: **one brain, many front-ends.** Every Kerberos operation lives in
`kerberos.py` and is reachable without GTK, so the CLI works over SSH and the
tests run without a display. The GUI is a consumer, not the owner.

## Configuration

`~/.config/krbctl/accounts.json` (mode `0600`). No passwords in it — those live
in the keyring, keyed by principal.

```json
{
  "version": 1,
  "accounts": [
    {
      "id": "user-example-com",
      "principal": "user@EXAMPLE.COM",
      "label": "Work",
      "method": "keytab",
      "keytab": "~/.keytab",
      "cache": "",
      "auto_renew": true,
      "remember_password": true,
      "warn_minutes": 15
    }
  ],
  "prefs": { "poll_seconds": 30, "notify": true, "auto_renew_global": true }
}
```

`cache: ""` means "whatever the session default is" — which respects
`KRB5CCNAME` and `/etc/krb5.conf`'s `default_ccache_name`, so a KCM or KEYRING
setup needs nothing special.

### Seeding

First run fills this file in, in two steps, and you normally never edit it:

| Found | Account created |
|---|---|
| `~/.keytab` | `method: "keytab"`, `auto_renew: true` |
| A live cache but no keytab | `method: "session"`, `auto_renew: false` |

Only **user** keytabs are considered (`~/.keytab`, `~/.config/krb5.keytab`).
`/etc/krb5.keytab` is deliberately ignored: that is the machine account
(`HOSTNAME$@REALM`), i.e. the computer's own identity to the domain, not a
user's. It is `0600 root:root` so an unprivileged run could not read it anyway,
but a ticket manager should not hold a host's domain credential even when it
could.

The keytab wins because it is the only one of the two that supports unattended
renewal. A `session` account is a ticket your login already obtained — SSSD puts
AD tickets in `KCM:` or `KEYRING:` — so there is no secret for the app to hold
and nothing for it to renew with. It observes the ticket and says so if you ask
it to renew.

The seeded session account deliberately keeps `cache: ""` rather than the real
cache name. A KCM name looks like `KCM:1014801116:76132`, and that trailing
number is the login session id: storing it would work until you logged out and
then silently read the wrong place. Leaving it empty follows the session, which
is what plain `klist` does.

## Gotchas worth knowing

* **Locale.** `klist` prints dates through `strftime("%x")`. On a Greek desktop
  `07/11/2026` is 7 November; under `LC_ALL=C` the same ticket prints
  `11/07/2026`. Every subprocess therefore runs with `LC_ALL=C`, and the parser
  assumes month-first. Mixing the two shifts a ticket by months.
* **The TGT is not the last row.** `klist` lists service tickets after the
  `krbtgt/` row, and those expire after it. The parser takes the timestamp from
  the `krbtgt/` row specifically.
* **Passwords never touch argv.** `kinit --password-file=STDIN` and a `ktutil`
  script on stdin, so nothing sensitive appears in `ps`.
* **`ktutil addent` still needs the KDC** to derive the salt, so creating a
  keytab requires the VPN up and the correct password — it is not offline.
* **Auto-renew never spends a stored password.** Only keytab accounts renew
  unattended; password accounts renew when you press the button.
* **The tray icon must advertise no `IconName`.** The icon is drawn at runtime
  from the installed PNG and shipped in `IconPixmap`. A StatusNotifierItem host
  that finds `IconName` set draws that theme icon *instead* of the pixmap, so
  any name here silently replaces the drawing — on Noctalia the leftover name
  `dialog-password-symbolic` showed up as a keyhole and the real icon never
  appeared. `IconName` is deliberately the empty string.
* **The tray icon is resolved through the icon theme, not the payload.**
  `install.sh` keeps no PNGs in `share/krbctl`, so `icons.app_icon_path()`
  searches `XDG_DATA_HOME`/`XDG_DATA_DIRS` for `hicolor/*/apps/krbctl.png`,
  nearest committed size first. If it finds nothing it falls back to the drawn
  plate rather than rendering a blank square.

## Requirements

`krb5-workstation` (or `krb5-user` on Debian), plus GTK4, libadwaita,
PyGObject, pycairo and libsecret. Verified on Fedora 45 with GTK 4.24 /
libadwaita 1.10.
